## TL;DR

Peter J. Denning 于 1970 年在 *ACM Computing Surveys* 发表的这篇综述，是虚拟内存领域的**奠基性文献**。论文首次把此前散落在各个系统（Atlas、Multics、IBM OS/360）中的实践提炼为一个统一的概念框架：**把程序使用的地址（逻辑地址）与内存硬件的地址（物理地址）分离，由系统自动完成映射**。论文系统比较了分段与分页两条实现路线，指出存储利用率低、抖动（thrashing）、装入成本高三类问题，并从理论角度论证它们可以通过合理的软硬件组合加以控制。其中最重要的贡献是**工作集模型（Working Set Model）**——它把"一个进程当前真正需要哪些页面"形式化，既解释了抖动的原因，也给出了预防抖动的方法。

> 一句话概括：==虚拟内存让程序员看到一个连续、私有、受保护的地址空间，而操作系统在背后把它映射到碎片化的物理内存上==，并用一个精巧的"最近访问集合"理论让这件事高效运转。

## 1. 背景与动机

### 1.1 1960 年代的存储困境

在虚拟内存普及之前，程序员直接面对物理内存：

- **覆盖技术（Overlay）**：程序员手工把程序切成若干块，块与块在运行时互相覆盖。写错覆盖关系就会导致程序崩溃。
- **分区分配**：内存被划分为若干固定或可变分区，程序必须整体装入一个连续分区。这带来**外部碎片**——总空闲空间够用，但没有一块足够大的连续区域。
- **多道程序设计的矛盾**：想让多个程序同时驻留内存以提高 CPU 利用率，但每个程序都要占据连续空间，且大小不可预测。

### 1.2 三个驱动力

Denning 在开篇明确指出自动存储分配的三个来源：

| 驱动力 | 含义 |
|--------|------|
| **程序模块化**（program modularity） | 程序应当由独立编译、可动态链接的模块组成，而不是一个整体 |
| **机器独立性**（machine independence） | 程序不应依赖具体的内存大小和布局 |
| **资源共享**（resource sharing） | 多个用户/进程需要安全地共享物理内存和代码 |

这三个目标指向同一个解法：**在程序看到的地址与硬件地址之间插入一层抽象**。Denning 把这种抽象称为 virtual memory（虚拟内存），并给出经典定义：

> 在虚拟内存中，程序用来标识信息的地址与内存系统用来标识物理存储位置的地址是**有区别的**，程序生成的地址会被**自动翻译**成对应的机器地址。

### 1.3 一个思想实验：一级存储（One-Level Store）

论文反复强调一个愿景：让整个存储系统——快速主存与慢速辅存——表现为**一个统一的、连续的存储空间**。程序员不必关心数据此刻是在内存还是磁盘上，系统按需自动搬运。这一思想直接影响了后来所有操作系统的存储层次设计，也是今天"内存-SSD"混合存储的哲学源头。

## 2. 核心思想

### 2.1 地址分离：虚拟内存的本质

Denning 把虚拟内存抽象成三个层次的地址空间：

```
程序地址空间 (virtual address space)
        │  地址映射 f: 逻辑地址 → 物理地址
        ▼
物理地址空间 (physical address space)
        │  必要时换入/换出
        ▼
辅存 (secondary storage)
```

**关键洞察**：一旦引入地址映射这个"间接层"，很多原本困难的问题就迎刃而解——

- 程序可以认为自己拥有整个地址空间（解决机器独立性）
- 不同程序可以使用相同的地址而不冲突（解决共享与保护）
- 程序可以比物理内存更大（解决容量限制）
- 数据可以在内存与辅存之间自由移动而不影响程序正确性（解决自动分配）

这一"加一层间接"的思想，后来成为计算机系统的通用范式——==几乎任何系统难题都可以通过引入一个抽象层来解决==（正如 David Wheeler 所说："All problems in computer science can be solved by another level of indirection"）。

### 2.2 两种实现路线：分段 vs 分页

论文用大量篇幅对比了两条实现路线，这是全文最精彩的部分之一。

#### 分段（Segmentation）

- 按程序的**逻辑结构**划分：代码段、数据段、栈段、各个过程/模块各成一段
- 每段长度可变，段内地址连续
- 地址形式：`(段号, 段内偏移)`，由段表映射
- **优点**：符合程序员对程序结构的认知，便于共享（可共享整个过程段）和保护（按段设置权限）
- **缺点**：段长可变导致**外部碎片**；段可能很大，换入换出成本高

#### 分页（Paging）

- 把地址空间和物理内存都切成**固定大小的块**（页 / 页框，page / page frame）
- 地址形式：`(页号, 页内偏移)`，由页表映射
- **优点**：固定大小消除了外部碎片；管理简单；换入换出粒度小
- **缺点**：页对程序是"不可见"的，一个页可能跨越逻辑模块边界；**内部碎片**（最后一页用不满）

#### 对比与融合

Denning 的结论是两者互补而非互斥：分段提供**逻辑视图**，分页提供**物理效率**。现代系统普遍采用**段页式（paged segmentation）**——先分段、段内再分页，兼得两者之长。x86 架构的分段+分页内存模型正是这一思想的体现。

| 维度 | 分段 | 分页 |
|------|------|------|
| 划分依据 | 程序的逻辑模块 | 固定大小的物理块 |
| 大小 | 可变 | 固定 |
| 碎片类型 | 外部碎片 | 内部碎片 |
| 对程序员可见 | 是 | 否 |
| 主要优势 | 共享与保护 | 利用率与效率 |

### 2.3 地址映射机制

论文讨论了映射的硬件支持：

- **段表 / 页表**：==每个进程一张，记录逻辑单元到物理位置的映射==
- **相联存储器（associative memory）/ TLB**：缓存近期使用的映射，避免每次地址转换都查表
- **保护位**：每个表项附带读/写/执行权限，实现进程隔离

这些讨论pref figure了今天 MMU（内存管理单元）和 TLB（快表）的标准设计。

### 2.4 请求调页与置换算法

当程序访问的页不在内存时，触发**缺页中断（page fault）**，系统从辅存调入该页。如果内存已满，必须选一页换出——这就是**页面置换算法**的问题。Denning 系统分析了几种策略：

| 算法 | 策略 | 特点 |
|------|------|------|
| **Optimal (MIN)** | 换出未来最晚才用到的页 | 理论最优，但需要预知未来，不可实现；作为衡量基准 |
| **FIFO** | 换出最早调入的页 | 实现简单，但性能差，存在 **Belady 异常**（页框增加反而缺页率上升） |
| **LRU** | 换出最近最久未用的页 | 利用局部性原理，效果接近最优，但硬件实现成本高 |
| **Working Set** | 换出不在当前工作集中的页 | Denning 自己提出的方案，见下文 |

### 2.5 抖动（Thrashing）与工作集模型

这是全文的高潮。Denning 观察到一种病态现象：当内存中同时运行的进程太多时，每个进程分到的页框太少，导致频繁缺页；系统忙于换入换出，CPU 利用率急剧下降——这就是**抖动**。

**抖动的正反馈循环**：

```
进程增多 → 每进程页框减少 → 缺页率上升 → 更多时间用于换页
    ↑                                              │
    └──── 系统试图通过增加并发来提升吞吐 ←──────────┘
```

**工作集模型**是 Denning 给出的解法。定义：

- 工作集 $W(t, \Delta)$ 是进程在时刻 $t$ 之前的 $\Delta$ 时间窗口内访问过的页面集合
- $\Delta$ 称为**工作集窗口**，代表"最近的过去"能预测"最近的将来"
- 工作集的大小 $w(t, \Delta) = |W(t, \Delta)|$ 随程序执行阶段动态变化

**核心原则**（Working Set Model 的调度策略）：==只有当系统能为每个进程分配至少其工作集大小的页框时，才让该进程运行==。如果所有进程的工作集之和超过内存容量，就**挂起**部分进程，而不是让它们一起抖动。

这一模型的深刻之处在于：

1. 它把"程序需要多少内存"从一个静态问题变成一个**随执行阶段动态变化**的量
2. 它基于**时间局部性**原理——过去 $\Delta$ 时间内访问的页，很可能在接下来继续被访问
3. 它把内存管理从"页面置换"提升为"**进程调度与内存分配联合决策**"

工作集模型至今仍是操作系统内存管理的核心概念之一，Windows 和 Linux 的某些调度策略都能看到它的影子。

## 3. 论文的贡献与影响

### 3.1 理论贡献

- **统一概念框架**：把分散的实践经验提炼为严谨的理论体系，让虚拟内存从"技巧"变成"科学"
- **形式化方法**：用集合、映射、时间窗口等数学工具描述存储管理，使后续研究有共同语言
- **局部性原理的早期阐述**：工作集模型是程序局部性（locality）最经典的形式化之一

### 3.2 对工业界的影响

| 系统/技术 | 与本文的关系 |
|-----------|-------------|
| **Multics** (1965-1969) | 分段+分页的先驱实践，本文的理论总结对象之一 |
| **Unix / Linux** | 请求调页、页表、Copy-on-Write 等机制延续本文框架 |
| **Windows NT** | 工作集模型直接影响其内存管理器设计 |
| **现代 JVM / Go runtime** | 垃圾回收中的分代假设、局部性利用与工作集思想同源 |
| **数据库缓冲池管理** | LRU-K、Clock 等页面置换算法与本文讨论一脉相承 |

### 3.3 跨领域影响

虚拟内存的思想远远超出了操作系统：

- **数据库**：==Buffer Pool 管理本质上是"数据库的虚拟内存"==
- **编程语言**：垃圾回收器的分代假设利用了与工作集相同的局部性原理
- **分布式系统**：缓存一致性、页面迁移与分布式内存管理共享同一套抽象
- **今天的 AI 系统**：LLM 的 KV Cache 管理（如 vLLM 的 PagedAttention）直接借用了分页思想，可视为虚拟内存在 AI 时代的回响

## 4. 局限与批评

尽管这篇论文影响深远，仍有一些时代局限：

- **综述性质**：作为 *Computing Surveys* 的文章，它主要整理了已有工作，原创的算法不多（工作集模型除外，该模型源自 Denning 1968 年的论文）
- **硬件假设**：讨论基于 1960 年代的硬件（相联存储器昂贵、TLB 刚出现），今天的硬件环境已大不相同
- **单一处理器假设**：没有涉及多核、NUMA 架构下的内存管理问题
- **工作集窗口的选择**：$\Delta$ 取多大没有理论上的最优解，实践中依赖经验调优

但这些局限丝毫不减损其经典地位——==它建立的是概念框架，而框架的生命力恰恰在于能被不断在新的硬件和场景中重新实现==。

## 5. 延伸阅读

- **[Denning, "The Working Set Model for Program Behavior" (1968)](https://dl.acm.org/doi/10.1145/362875.362888)**：工作集模型的原始论文，更紧凑地介绍了核心思想
- **[Denning, "A Third Generation Computer" / 后续回顾文章](https://dl.acm.org/doi/10.1145/356612.356620)**：作者本人对虚拟内存历史的反思
- **[《操作系统概念》(Silberschatz et al.) 第 8-9 章](https://www.os-book.com/)**：现代教材对虚拟内存的讲解，可以对照阅读看概念如何演化
- **[Denning & Van Horn, "Virtual Memory" 之前的先驱工作](https://en.wikipedia.org/wiki/Virtual_memory)**：Atlas 计算机（1962）首次实现分页，值得了解历史背景
- **[vLLM 的 PagedAttention 论文 (2023)](https://arxiv.org/abs/2309.06180)**：看分页思想如何在大模型时代焕发生机，是理解"经典概念如何迁移到新领域"的绝佳案例
