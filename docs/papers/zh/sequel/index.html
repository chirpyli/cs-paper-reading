SEQUEL：一种结构化的英语查询语言

Donald D. Chamberlin · Raymond F. Boyce

IBM Research Laboratory, San Jose, California

摘要

本文提出一种结构化英语查询语言（SEQUEL）的数据操作设施，它可用于访问集成关系数据库中的数据。SEQUEL 不借助绑定变量与量词的概念，而是识别出一组作用于表格结构上的简单操作；可以证明，这些操作具有与一阶谓词演算等价的能力。SEQUEL 向用户呈现一组一致的、由英语关键词构成的模板，这些模板反映了人们使用表格获取信息的方式。此外，SEQUEL 用户能够以结构化的方式组合这些基本模板，从而构造更复杂的查询。SEQUEL 既面向专业程序员，也面向不经常使用数据库的用户，作为数据库子语言而设计。

《计算评论》分类：3.5，3.7，4.2

关键词与短语：查询语言；数据库管理系统；信息检索；数据操作语言

1 引言

随着计算机系统变得越来越先进，我们看到一个逐渐从过程式问题说明走向声明式问题说明的演进。这一演进有两个主要原因。第一，必须找到降低专业程序员软件成本的途径。程序创建、维护与修改的成本一直在飞速上升。结构化程序设计的概念 [1, 2] 被提出，用以简化编程并降低软件成本。第二，越来越需要让非专业用户能够与格式化数据库进行有效通信。计算机产业的许多成功，依赖于开发出训练有素的计算专家之外的用户群体。

本文提出的结构化英语查询语言（SEQUEL）的研究工作，与声明式问题说明的这一趋势是一致的。它试图识别数据库用户所需的基本功能，并开发一组简单而一致的规则，把这些功能应用于数据。这些规则旨在简化专业人员的编程，并使新一类用户能够与数据库交互。

这里有必要简要讨论一下这类新用户。有些用户与计算机交互的频率极低，或者交互毫无结构，以至于他们不愿学习查询语言。对这些用户而言，自然语言或菜单选择 [3, 4] 似乎是最可行的替代方案。然而，还有一大类用户，他们虽不是计算机专家，却愿意学习用一种相当高级的、非过程式的查询语言与计算机交互。这类用户的例子包括会计师、工程师、建筑师和城市规划师。SEQUEL 正是为这类用户而设计的。因此，SEQUEL 强调简单的数据结构与操作。

在一系列论文中，E. F. Codd [5–9] 引入了关系数据模型。它似乎是最简单的通用数据结构，并提供了最大程度的数据独立性。本文只讨论规范化的关系，它可以看作具有 $n$ 列和可变行数目的表，如图 1 所示。

EMP NAME SAL MGR DEPT
SMITH 10000 JONES TOY
JONES 12000 ANDERSON FURNITURE
LEE 10000 THOMAS APPLIANCES

图 1. 描述雇员的关系。

除了引入关系数据结构之外，Codd 还定义了一种语言 [9]，用于以关系格式访问或引用数据。这种语言以及类似的语言（COLARD [10]、RIL [11]）都基于一阶谓词演算。用这些语言编写的查询通常需要：

  1. 用户定义额外的变量，这些变量以某一关系中的行或行的一部分作为值；
  2. 用户用布尔表达式以及全称量词和存在量词来陈述查询。

Knuth [12] 指出，FORTRAN 中的大多数语句都相当简单。我们相信，对数据库的查询也是如此。此前，我们提出了一种名为 SQUARE [13, 14] 的数据子语言，它提供了一种简单直接的方式来引用表中的数据。SQUARE 使用户能够以面向集合的表查找（而不是逐行处理的风格）来描述数据选择。这使得量词得以消除，也消除了用于关联多个表中信息的显式连接项。因此，SQUARE 用户不需要谓词演算的数学造诣，就能对表进行相对简单的引用。然而，已有研究表明 [14]，SQUARE 语言是完备的：任何可用谓词演算表达的查询，都可用 SQUARE 表达。

本文试图总结 SQUARE 工作的要点，并报告后续工作：开发一种对未受训练的用户而言比 SQUARE 简洁数学记法更熟悉的记法。在开发这种新语法时，我们始终记住自顶向下结构化程序设计的观念、对线性记法的需求，以及对可读、易维护、易修改程序的需求。由此得到的语法，最好被描述为块结构的英语关键词语法。

2 SQUARE 概要

本节通过一系列例子回顾 SQUARE 查询语言的主要特性。这些特性的更精确定义见其他文献 [13]。在后续各节中，我们将介绍 SEQUEL 的查询设施，并把它应用于同一组例子（以及其他例子）。

本节及后续各节的所有例子都取自一个描述百货商店运营的数据库，该数据库由五张表组成：

EMP     (NAME, DEPT, MGR, SAL, COMM)
SALES   (DEPT, ITEM, VOL)
SUPPLY  (SUPPLIER, ITEM, VOL)
LOC     (DEPT, FLOOR)
CLASS   (ITEM, TYPE)

EMP 表为每位商店雇员保存一行，给出其姓名、部门、经理、工资以及上一年的佣金。SALES 表给出每个部门销售每种商品的数量（年度计数）。SUPPLY 表给出每家供应公司向商店供应各种商品的数量（年度计数）。LOC 表给出每个部门所在的楼层，CLASS 关系把所售商品划分为各种类型。

SQUARE 中最简单的表达式称为映射（mapping），如 Q1 所示。

Q1. 找出玩具部门中雇员的姓名。

映射：  EMP('TOY')
域：    DEPT
范围：  NAME

一个映射由表名（EMP）、域（DEPT）、范围（NAME）和一个实参（'TOY'）组成。映射的值是这样一组值的集合：在指定表中，其域列上的关联值与实参相匹配的行，其范围列上的值构成该集合。映射模拟了人们使用表格的方式。在这个例子中，要找出玩具部门中雇员的姓名，人们可能会沿着 EMP 表的 DEPT 列向下查看，找到 'TOY' 的表项，然后列出对应的 NAME 表项。

映射的域或范围都可以涉及多个列，如 Q2 所示。Q2 的结果是一个由（姓名，工资）对组成的列表。

Q2. 找出玩具部门中且经理为 Anderson 的雇员的姓名与工资。

映射：  EMP('TOY', 'ANDERSON')
域：    DEPT, MGR
范围：  NAME, SAL

映射可以通过把一个映射应用于另一个映射的结果来进行组合，如 Q3 所示。

Q3. 找出二楼各部门所售的商品。

SALES ∘ LOC('2')
   ITEM       DEPT     DEPT     FLOOR

从过程性的角度看，LOC 映射产生一组部门，这组部门作为实参提供给 SALES 映射；结果是该集合中任一部门所售商品的集合。从描述性的角度看，该查询以自顶向下、从左到右的方式书写，十分接近英语表达。用户希望从 SALES 中收到 ITEM，条件是 DEPT 满足某个准则；该准则被表达为：DEPT 取自 LOC 中 FLOOR 值为 '2' 的那些行。

一般而言，映射的结果是一组值或一组值的元组。一组值可以进一步通过应用数学函数来处理，例如 SUM、COUNT、AVG、MAX 或 MIN：

Q4. 找出鞋类部门雇员的平均工资。

AVG(EMP'('SHOE'))
 SAL       DEPT

EMP 上的撇号表示在应用 AVG 函数之前，不从集合中消除重复的工资值。

由映射产生的集合还可以使用标准的集合运算符并、交、差来操作，如 Q5 所示。

Q5. 找出由 Levi 供应且在男装部销售的商品。

SUPPLY('LEVI') ∩ SALES('MEN')
   ITEM        SUPPLIER    ITEM     DEPT

例子 Q6 展示了如何把 SQUARE 的基本特性嵌套起来形成复杂查询。

Q6. 找出二楼各部门销售的 A 类商品的总销量。

SUM(SALES(CLASS('A'), LOC('2')))
 VOL    ITEM, DEPT   ITEM   TYPE   DEPT   FLOOR

3 SEQUEL 的基本特性

SEQUEL 语言在能力上与 SQUARE 等价，但它是为那些更适应英语关键词格式、而非 SQUARE 简洁数学记法的用户设计的。我们将通过回顾上一节的示例查询，并引入一些新例子，来介绍 SEQUEL 的特性。

和 SQUARE 一样，最简单的 SEQUEL 表达式是一个映射，它指定一张表、一个域、一个范围和一个实参，如 Q1 所示。

Q1. 找出玩具部门中雇员的姓名。

SELECT  NAME
FROM    EMP
WHERE   DEPT = 'TOY'

该映射返回满足测试条件 DEPT = 'TOY' 的全部姓名的集合。

SEQUEL 向用户呈现一个一致的模板来表达简单查询。用户只需指定希望 SELECT 的列、从中选择查询列的表（FROM），以及返回行所满足的条件（WHERE）。SELECT-FROM-WHERE 块是该语言的基本构件。在交互式系统中，这个模板可以呈现给用户，由用户填空。对于简单映射，SELECT-FROM-WHERE 块与 GIS [15] 和 IQF [16] 所采用的方法是类似的。

如果省略映射的 WHERE 子句，映射将返回一个投影，即取自整张表的所选列的唯一值列表：

Q1.1. 列出 EMP 表中的所有部门。

SELECT  DEPT
FROM    EMP

类似地，如果省略 SELECT 子句和 FROM 一词，映射将返回所有满足 WHERE 子句条件的行（作为完整的行）：

Q1.2. 列出描述工资大于 8000 的雇员的那些行。

EMP WHERE SAL > '8000'

和 SQUARE 一样，域或范围都可以涉及多个列，如 Q2 所示。

Q2. 找出玩具部门中且经理为 Anderson 的雇员的姓名与工资。

SELECT  NAME, SAL
FROM    EMP
WHERE   DEPT = 'TOY'
AND     MGR = 'ANDERSON'

SEQUEL 高度显式的语法使我们能够在 WHERE 子句中构造逻辑测试。例如，值比较可以使用由列名构成的表达式，也可以使用相等以外的准则。Q2.1 说明了这些特点。

Q2.1. 找出属于 'ADMIN' 部门、或者工资与佣金之和超过 10000 的雇员的姓名。

SELECT  NAME
FROM    EMP
WHERE   DEPT = 'ADMIN'
OR      SAL + COMM > '10000'

和 SQUARE 一样，一个映射可以应用于另一个映射的结果，如 Q3 所示。

Q3. 找出二楼各部门所售的商品。

SELECT  ITEM
FROM    SALES
WHERE   DEPT =
        SELECT  DEPT
        FROM    LOC
        WHERE   FLOOR = '2'

再次值得注意到这个例子中自顶向下结构化程序设计的影响。在书写其基本的 SELECT-FROM-WHERE 块时，用户写到希望为 SALES 的 DEPT 字段指定一个匹配准则的位置。他既可以指定一个简单的匹配值（如 DEPT = 'TOY'），也可以指定一个内部映射，如 Q3 所示。如果他需要指定另一个映射，只需再填写一个 SELECT-FROM-WHERE 块。同样，交互式系统可以在这一过程中提供帮助。于是，该语言被化约为少数几个基本构件，以及一组用于组合这些构件的简单规则。

在 SEQUEL 中，组合查询的外层映射与内层映射之间的匹配准则是显式陈述的（在 Q3 中为 =）。我们利用这种显式性，允许把任意关系运算符 =、≠、>、≥、<、≤ 作为匹配准则。一般而言，内层映射产生一组值，外层映射返回指定表（在 Q3 中为 SALES）的那些行：这些行的域值（在 Q3 中为 DEPT）按匹配准则与内层映射产生的任一值相比较。因此，Q3 返回二楼任一部门所售的商品。通过在匹配准则之后使用 ALL 一词，我们可以让外层映射返回这样的行：其域值与内层映射产生的所有值相比较都满足该准则。于是，把 Q3 中的 'DEPT =' 改为 'DEPT = ALL'，将返回二楼所有部门都销售的商品。这说明了 SQUARE 中所谓的“合取映射”（conjunctive mapping）[13]。Q3.1 是进一步的例子。

Q3.1. 找出工资高于鞋类部门任一雇员的雇员。

SELECT  NAME
FROM    EMP
WHERE   SAL > ALL
        SELECT  SAL
        FROM    EMP
        WHERE   DEPT = 'SHOE'

一般而言，任何比较运算符（>、< 等）都可以在其中一侧或两侧用 ALL 修饰，以实现一项与一个集合、或一个集合与另一个集合之间的比较。当某个集合在没有 ALL 一词的情况下参与比较时，默认含义是“某个”（some）。

和 SQUARE 一样，我们可以把数学函数放在 SELECT 子句中，从而把它应用于映射的结果，如 Q4 所示。

Q4. 找出鞋类部门雇员的平均工资。

SELECT  AVG(SAL)
FROM    EMP
WHERE   DEPT = 'SHOE'

在 SEQUEL 中，重复值的问题由以下默认规则解决：如果数学函数作用于映射的结果，映射保留重复值；否则，重复值被消除。这些默认值可以被显式覆盖。

Q4 是 SEQUEL 中一条一般规则的例子：SELECT 子句可以包含由所用表中的列名构成的任意算术表达式。如果表达式中出现数学函数，其参数取自该表中满足 WHERE 子句的那些行的集合。例如：

Q4.1. 列出鞋类部门的每位雇员及其与该部门平均工资的差额。

SELECT  NAME, SAL - AVG(SAL)
FROM    EMP
WHERE   DEPT = 'SHOE'

并运算符与交运算符在 SEQUEL 中的用法与在 SQUARE 中完全相同，如 Q5 所示。

Q5. 找出由 Levi 供应且在男装部销售的商品。

SELECT  ITEM
FROM    SUPPLY
WHERE   SUPPLIER = 'LEVI'
∩
SELECT  ITEM
FROM    SALES
WHERE   DEPT = 'MEN'

重要的是区分：在一个映射内部使用 AND 或 OR 的效果，与在两个映射之间使用并或交的效果。在前一种情况下，由 AND/OR 分隔的子句作用于表的同一行；在后一种情况下，两个映射被独立应用，并/交作用于它们的结果之上。为说明这一点，假设 EMP 表包含以下表项：

NAME DEPT MGR
JOHN SHOE BOB
FRED SHOE FRANK
FRED TOY BOB
BILL TOY FRANK

下面是两个示例查询的结果：

Q5.1.

SELECT  NAME
FROM    EMP
WHERE   DEPT = 'SHOE'
AND     MGR = 'BOB'

结果：JOHN。

Q5.2.

SELECT  NAME
FROM    EMP
WHERE   DEPT = 'SHOE'
∩
SELECT  NAME
FROM    EMP
WHERE   MGR = 'BOB'

结果：JOHN, FRED。

这里重复例子 Q6，以展示 SEQUEL 的特性如何嵌套起来形成复杂查询。

Q6. 找出二楼各部门销售的 A 类商品的总销量。

SELECT      SUM(VOL)
FROM        SALES
WHERE       ITEM =
            SELECT  ITEM
            FROM    CLASS
            WHERE   TYPE = 'A'
AND         DEPT =
            SELECT  DEPT
            FROM    LOC
            WHERE   FLOOR = '2'

请注意，在这个查询中，缩进被用来分隔各个映射并显示查询的结构。在实践中，把缩进设为可选、并以分号结束每个映射可能更加方便。那么在上面的查询中，TYPE = 'A' 之后会有一个分号，而 FLOOR = '2' 之后会有两个分号。

4 附加概念

SQUARE 查询语言的主要动机，是开发一种访问关系数据库的简便手段。我们认为，应用谓词演算及其变量与量词概念，对普通用户而言要求过高。SQUARE 成功地避开了绑定变量与量词的概念，但当需要把表中某一特定行的值与另一行或多行的值相关联时，它仍然需要一个自由变量。典型情况下，SQUARE 中的这类查询具有如下形式：

自由变量 : 测试

自由变量代表表中的一行。查询的结果取自测试为真的那些行中的值的集合。关于 SQUARE 中自由变量的更完整描述见其他文献 [13, 14]。例子 Q7 说明了这一概念。

Q7. 找出管理超过十名雇员的经理的姓名。

x    EMP : COUNT(EMP(x)) > 10
NAME         NAME   MGR   NAME

请注意，在 Q7 中，自由变量 x 用于把一位经理的姓名与表示其雇员的一组行相关联，以便对这组行进行计数。经验表明，这种“分组”在查询中出现得相当频繁。因此，SEQUEL 提供了一种方式，可以按照一个或多个列的值把表中的行划分为组，其方式类似于信息代数 [17] 中“群”（group）的概念。GROUP BY 子句是可选的，可以附加到 SEQUEL 中的任何 FROM 子句上，其效果是：该表中的行按列值相匹配的方式分组。例如，如果某个查询包含子句 FROM EMP GROUP BY MGR，那么为了这个查询，EMP 表的行将按 MGR 值匹配的方式形成若干组。在这样的子句范围内，对列引用有某些限制。分组列（上例中的 MGR）可以被引用，因为它在每组中只有一个值。可以使用对列值的数学函数，其隐含规则是：它们以一组列值作为参数，并为该组返回单一值。例如，在子句 FROM EMP GROUP BY MGR 的范围内，函数 AVG(SAL) 将为每位经理返回其雇员的平均工资。其他函数（如 SUM、COUNT 和 MAX）以类似方式工作。不属于分组准则的列，除了作为返回每组单一值的函数的参数之外，不得被引用。现在用 SEQUEL 重写例子 Q7，以说明 GROUP BY 特性。

Q7. 找出管理超过十名雇员的经理的姓名。

SELECT  MGR
FROM    EMP GROUP BY MGR
WHERE   COUNT(NAME) > 10

例子 Q8 进一步说明了分组的概念。

Q8. 列出各部门以及该部门雇员工资的总和。

SELECT  DEPT, SUM(SAL)
FROM    EMP GROUP BY DEPT

如果需要，用户可以由常量构造一个字面量元组或整张表在查询中使用。Q9 说明了这一点，也说明了特殊函数 SET 的用法，它返回由 GROUP BY 子句分组在一起的值的集合。

Q9. 找出这样的部门：其中有名为 SMITH、JOHNSON 和 HUGHES 的雇员，且他们的经理都是 JONES。

SELECT  DEPT
FROM    EMP
WHERE   SET(NAME, MGR) =
          { <'SMITH', 'JONES'>,
            <'JOHNSON', 'JONES'>,
            <'HUGHES', 'JONES'> }

还有少数查询，在 SQUARE 中需要自由变量来解决列引用中的歧义。在大多数情况下，在 SEQUEL 中可以通过用表名限定列名来解决歧义。Q10 说明了这一点，它实现了 Codd [7] 所称的 SALES 表与 SUPPLY 表在 ITEM 列上的“连接”（join）。

Q10. 列出 SALES 与 SUPPLY 中 ITEM 值相匹配的行，并把它们连接起来。

SALES, SUPPLY
WHERE SALES.ITEM = SUPPLY.ITEM

在仅靠表名不足以解决歧义的情况下（因为同一表名在查询中出现多次），SEQUEL 允许把一个任意选取的块标签附加到某个映射上，并用它来限定列引用。Q11 说明了这一点。

Q11. 找出工资高于其经理工资的雇员的姓名。

B1: SELECT  NAME
    FROM    EMP
    WHERE   SAL >
            SELECT  SAL
            FROM    EMP
            WHERE   NAME = B1.MGR

在这个查询中，标记为 B1 的外层映射返回所有满足以下测试的行的 NAME 值：B1 行的 SAL 值必须大于其 NAME 与 B1 行的 MGR 相同的那一行的 SAL 值。

5 与基于谓词演算的语言的比较

本节说明，用基于一阶谓词演算的语言 [9–11] 表达的查询，与用 SEQUEL 表达的查询，在理解方式上存在差异。基于演算的语言允许用对所给关系中各个行的测试来描述查询。

考虑用演算表达查询 Q6：

Q6. 找出二楼各部门销售的 A 类商品的总销量。

SUM{x[VOL] ∈ SALES :
      (∃y ∈ CLASS) ((y[ITEM] = x[ITEM]) ∧ (y[TYPE] = 'A'))
      ∧ (∃z ∈ LOC)   ((z[DEPT] = x[DEPT]) ∧ (z[FLOOR] = '2'))}

演算程序员必须关心：

  1. 设置三个变量 x、y 和 z，使它们依次遍历每张表；
  2. 存在量词与绑定变量的概念；
  3. 显式的连接项 "y[ITEM] = x[ITEM]" 与 "z[DEPT] = x[DEPT]"；
  4. 决定某个值是否属于输出集合的实际匹配准则。

然而，我们前面已经说明，这个查询在 SEQUEL 中只需组合三个映射块即可表达。当然，我们并不是说真正复杂的查询在 SEQUEL 中很容易表达；我们强调的是 SEQUEL 与更传统方法之间的差异。这种理解方式上的差异，在文献 [13] 中有更充分的讨论。

6 总结

本文提出了一种基于关系数据模型的数据子语言的数据操作设施（DMF）。这种数据子语言也被用作数据定义设施（DDF）的基础 [18]。DDF 与 DMF 共同构成一种面向非计算机专业用户的查询设施。简单的块结构英语关键词语法，以及对表格的简单操作，使用户与 SEQUEL 系统交互时，比在面向演算的系统或传统过程式编程语言中所需要的训练和造诣都要少。SEQUEL 用户用集合表达式而不是逐行迭代来描述要访问的相关数据。由此产生的查询往往简洁、表达清晰，且易于编写、维护和修改。SEQUEL 查询的形式语法在附录中给出。

附录：SEQUEL 查询语法

说明：[ ] 表示可选项；| 表示可替换形式。

query ::= basic-query
        | basic-query ∩ query
        | basic-query ∪ query
        | basic-query - query
        | (query)

basic-query ::= [label:] sel-clause-list [where-clause];

sel-clause-list ::= sel-clause
                  | sel-clause-list, sel-clause

sel-clause ::= [SELECT expr-list FROM] table-name
               [GROUP BY col-name-list] [dup-code]

dup-code ::= DUPL | UNIQUE

expr-list ::= expr
            | expr-list, expr

col-name-list ::= col-name
                | col-name-list, col-name

where-clause ::= WHERE boolean

boolean ::= predicate
          | predicate AND boolean
          | predicate OR boolean
          | NOT boolean
          | (boolean)

predicate ::= comparand comp-op comparand

comp-op ::= [ALL] rel-op [ALL]
          | set-op

rel-op ::= = | ≠ | < | ≤ | > | ≥

set-op ::= = | ⊇ | ⊆ | ∈ | ∉

comparand ::= expr

expr ::= atom
       | expr + atom
       | expr - atom
       | expr × atom
       | expr / atom
       | (expr)
       | set-fn(col-name)

atom ::= col-name
       | table-name.col-name
       | label.col-name
       | constant
       | set-fn(col-name)

set-fn ::= SUM | COUNT | AVG | MAX | MIN | SET

literal ::= lit-table
          | lit-tuple
          | constant

lit-table ::= {lit-tuple-list}

lit-tuple-list ::= lit-tuple
                 | lit-tuple-list, lit-tuple

lit-tuple ::= <constant-list>

constant-list ::= constant
                | constant-list, constant

constant ::= 'string'
           | 'number'
